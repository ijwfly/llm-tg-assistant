# claude-tg — функциональная спецификация

Документ описывает, **что** делает claude-tg с точки зрения пользователя Telegram и
оператора, и **какие возможности Claude Code** доступны через мост и каким образом.
Детали внутренней реализации намеренно опущены.

---

## 1. Назначение и модель

claude-tg — отдельный демон, который держит связь с одним Telegram-ботом и запускает
процессы `claude` (Claude Code CLI) на машине, где работает. Пользователь пишет боту в
Telegram, бот отдаёт сообщение Claude Code, ответ возвращается в тот же чат.

**Ключевая единица — тема.** Каждая тема (topic) супергруппы с включёнными Topics, а также
каждый личный чат и каждая обычная группа — это отдельная сессия Claude Code со своими:

- контекстом разговора (session id, транскрипт на диске у Claude Code);
- рабочей директорией;
- собственным процессом `claude`;
- моделью, режимом прав, файлом персоны, флагом голосовых ответов;
- набором постоянных разрешений и историей последнего хода для `/retry`.

Темы полностью независимы: медленный ход в одной теме не задерживает остальные, сообщения
внутри одной темы обрабатываются строго по порядку.

| Где пишут боту | Сколько сессий |
|---|---|
| Супергруппа с Topics | По одной на каждую тему (основная цель проекта) |
| Личный чат | Одна на весь чат |
| Обычная группа без Topics | Одна на всю группу; `/project` не работает |

**Отличие от официального Telegram-плагина Claude Code** (функционально):

- много тем и много параллельных сессий вместо одной;
- есть управление жизненным циклом сессии: новый контекст (`/new`), `/compact`,
  подключение к сессии из терминала (`/resume`), смена директории, модели и прав на лету;
- доставку ответов в Telegram выполняет сам демон, а не модель по своему усмотрению, поэтому
  ответ приходит всегда; ответы, не доставленные из-за сбоя, доезжают после перезапуска;
- опрос Telegram никогда не сдаётся при сетевых ошибках.

## 2. Доступ и безопасность

Два независимых замка:

- **`allowed_users`** — кто может управлять ботом. Список числовых Telegram id, обязателен и
  не может быть пустым. Сообщение или нажатие кнопки от любого другого пользователя
  игнорируется **молча**: ни ответа, ни индикатора «печатает». Id и username чужого
  попадают в лог демона, чтобы оператор мог его добавить. На нажатие кнопки чужой получает
  всплывающий тост «Not authorized».
- **`allowed_chats`** — где бот вообще говорит. Пустой список (по умолчанию) — в любом чате,
  откуда пишет разрешённый пользователь. Смысл замка: добавить бота в группу может кто
  угодно, а ответ бота (содержимое файлов, пути, вывод команд) прочитают все участники.

Токен бота не показывается нигде: он вырезается из текстов ошибок и **не передаётся**
дочерним процессам — ни `claude`, ни командам синтеза/распознавания речи. Модель,
выполняющая shell-команды, не может узнать токен через окружение.

Если задан `notify_chat`, демон пишет туда при старте
(`🌅 Я на месте. Бот @имя, режим prompt, тем в памяти: N, версия X`) и при остановке
(`⏹ Останавливаюсь.` плюс, если были прерваны ходы, сколько тем это затронуло и что
`/retry` повторит).

## 3. Команды бота

### 3.1 Общие правила

- Команда — первое слово сообщения, начинающееся с `/`. Суффикс `@имя_бота` отбрасывается
  (`/cd@my_bot /tmp` = `/cd /tmp`), регистр не важен. Остаток строки — аргумент.
- Команда может быть и подписью к фото/файлу.
- Команды `/whoami`, `/help`, `/topics`, `/cancel` не создают тему. Любая другая команда
  и любое обычное сообщение при первом обращении создают тему с новым session id и
  директорией `defaults.cwd` из конфига.
- **Любая команда, которую демон не знает, уходит в Claude Code как обычный ход.** Так
  работают `/compact`, `/agents`, `/doctor`, `/start` и прочие slash-команды CLI.
  Исключение: `/clear` перехватывается демоном и равен `/new`.
- В меню команд Telegram (кнопка «/») зарегистрированы: `new`, `compact`, `status`, `cd`,
  `model`, `perm`, `soul`, `sessions`, `resume`, `go`, `project`, `retry`, `voice`,
  `cancel`, `stop`, `topics`, `whoami`, `help`. `/compact` там для удобства, обрабатывает
  его сам Claude Code.

Ниже для каждой команды указано, что происходит с процессом `claude` и контекстом:
**«процесс перезапускается, контекст остаётся»** означает, что следующий ход продолжит тот
же разговор; **«контекст заново»** означает новый session id.

### 3.2 Контекст и процесс

**`/new`** (синоним `/clear`) — новый контекст в этой теме. Процесс останавливается,
выдаётся новый session id, старый транскрипт остаётся на диске (к нему можно вернуться
через `/sessions` и `/resume`). Ответ: `🆕 Новый контекст. Прошлая сессия сохранена на диске.`

**`/stop`** — погасить процесс `claude` этой темы, контекст сохранить. Следующее сообщение
поднимет процесс снова с тем же контекстом. Ответ: `⏸ Процесс остановлен, контекст сохранён.`
Нужен, например, чтобы вступила в силу правка файла персоны.

**`/cancel`** — прервать текущий ход. Обрабатывается вне очереди темы, поэтому срабатывает,
даже если тема «зависла» на длинном ходе. Строка прогресса заменяется на `🛑 Прервано.`,
контекст остаётся. Если ничего не идёт: `Нечего прерывать.` То же делает кнопка
«🛑 Прервать» под строкой прогресса.

**`/retry`** — повторить последний ход этой темы (текст последнего сообщения, отправленного
в Claude). Хранится на диске и переживает перезапуск демона; предназначен для повтора
после падения процесса или прерывания. Если хода ещё не было:
`Нечего повторять — в этой теме ещё не было хода.`

**`/status`** — состояние темы. Отвечает мгновенно даже посреди длинного хода. Поля:

```
Топик        chat_id:thread_id
Сессия       session id
Директория   путь
Модель       имя или «по умолчанию»
Права        режим (+ пометка «(только эта тема)», если переопределён)
Характер     путь к файлу персоны или «нет»
Голос        вкл / выкл
Процесс      «живой, N с» или «спит»
Ход          «идёт N с» или «нет»
Последний ход   1 м 12 с · $0.08 · 3 шага   (только если был ход после старта демона)
```

### 3.3 Директория и проекты

**`/cd <путь>`** — сменить рабочую директорию темы. `~` раскрывается. **Контекст начинается
заново**: сессия привязана к директории проекта. Ответ:
`📁 <путь>` / `Контекст начат заново — сессия привязана к директории.`
Несуществующая директория: `⚠️ нет такой директории: <путь>`.

**`/go [алиас]`** — то же, что `/cd`, но по короткому имени из секции `[projects]` конфига.
Без аргумента показывает список алиасов («Куда идём:») или подсказку, как их завести.
Неизвестный алиас: `Нет алиаса <x>. Список — /go без аргумента.`

**`/project [алиас | путь]`** — создать **новую тему форума** под проект и сразу привязать
её к директории. Имя темы — алиас или последний компонент пути. Требуется супергруппа с
включёнными Topics и право бота «Управление темами». В созданной теме появляется
`📁 <путь>` / `Тема готова, контекст чистый. Пиши сюда.`, а в исходной —
`✅ Тема <имя> открыта.` Без аргумента — справка и список алиасов. Несуществующая директория
или невозможность создать тему (не форум, нет права) — понятное сообщение об ошибке с
причиной. Цвет иконки темы выбирается по имени проекта, так что один проект всегда
получает один цвет.

**`/topics`** — список всех известных демону тем в формате `chat_id:thread_id — директория`
(или `Пока пусто.`).

### 3.4 Сессии Claude Code

**`/sessions`** — до 8 последних сессий Claude Code, транскрипты которых лежат в
стандартном хранилище Claude Code (`~/.claude/projects`, учитывается `CLAUDE_CONFIG_DIR`)
и чья рабочая директория совпадает с директорией темы. Для каждой: первые 8 символов id,
возраст («только что», «N мин назад», «N ч назад», «N дн назад») и название — своё
(custom title), сгенерированное Claude Code или первое сообщение пользователя (до 80
символов), иначе «без названия». Если пусто: `В <директория> сессий пока нет.`

**`/resume <id>`** — подключить к теме любую сессию Claude Code, в том числе начатую в
терминале. Достаточно уникального префикса от 4 символов. Тема **переезжает в директорию
из транскрипта** этой сессии, так что `/resume` заодно переключает проект. Ответ:

```
🔗 Подключилась к сессии <id>
Директория: <путь>

Если она сейчас открыта в терминале — закрой, иначе будут драться за один транскрипт.
```

Ошибки: нет аргумента (подсказка с примером), префикс короче 4 символов, сессия не
найдена, префикс неоднозначен (показываются до 6 кандидатов).

### 3.5 Настройки темы

**`/model [имя | default]`** — модель для этой темы. Без аргумента показывает текущую
(не сбрасывает). `/model default` (или `config`) возвращает модель из конфига. Смена
перезапускает процесс, контекст остаётся. Ответ: `🤖 Модель: <имя>`.

**`/perm [режим | default | forget]`** — права в этой теме (подробно в разделе 6). Без
аргумента показывает текущий режим, список всех режимов с пометкой `←` и накопленные
постоянные разрешения. `/perm default` возвращает режим из конфига. `/perm forget` забывает
все постоянные разрешения темы (`Забыла N правил. Снова буду спрашивать.`). Смена режима
перезапускает процесс, контекст остаётся. Неизвестный режим — `Не знаю режим <x>.` + список.

**`/soul [путь | off | default]`** — файл персоны для темы (раздел 8). Без аргумента
показывает `/status`. `off` — без персоны, `default` — как в конфиге, путь — свой файл
(`⚠️ нет такого файла`, если его нет). Перезапускает процесс, контекст остаётся.
Ответ: `🎭 Характер: <путь | выключен | из конфига>`.

**`/voice on|off`** (также `вкл`/`выкл`) — отвечать ещё и голосовым сообщением (раздел 9).
Требует настроенного `tts` в конфиге, иначе `Синтез не настроен: добавь tts в конфиг демона.`
Ответы: `🔊 Отвечаю ещё и голосом. Код и длинные простыни остаются текстом.` / `🔇 Только текст.`

### 3.6 Справка

**`/help`** — справка по командам демона и напоминание, что остальные slash-команды уходят
в Claude.

**`/whoami`** — `Твой id`, `Чат`, `Тема` (id темы или `—`). Нужен, чтобы заполнить
`allowed_users`, `allowed_chats`, `notify_chat`.

## 4. Что можно отправить боту

Всё, что не является командой демона, становится **ходом** — сообщением пользователя в
Claude Code. Ход собирается из частей в таком порядке: цитата ответа → вложения → текст →
подписи остальных фото альбома. Пустой ход (например, стикер без подписи) молча
отбрасывается.

| Что отправлено | Что получает Claude |
|---|---|
| Текст | Текст как есть |
| Фото | Файл скачивается в лучшем доступном качестве, в ход вставляется `[фото: /путь/к/файлу]` — Claude читает его сам инструментом Read |
| Альбом из нескольких фото | **Один** ход: все фото и все подписи. Первое фото ждёт остальные 700 мс |
| Документ | Скачивается, в ход вставляется `[файл имя: /путь]` |
| Голосовое | Скачивается. Если настроена транскрипция — в ход идёт распознанный текст, а в чат сразу эхо `🎤 _распознанный текст_` (до 300 символов), чтобы ошибка распознавания была видна. Без транскрипции — `[голосовое: /путь]` |
| Подпись к медиа | Используется как текст сообщения, в том числе для команд |
| Ответ (reply) на сообщение | В начало хода добавляется `[в ответ на твой ответ: «…»]` (если отвечают боту) или `[в ответ на сообщение: «…»]` — до 700 символов. Если пользователь выделил часть текста, цитируется именно она. Корневое сообщение темы форума в цитату не попадает |
| Правка отправленного сообщения | Новый ход с пометкой `[правка предыдущего сообщения]`; в чат — `✏️ Вижу правку — отвечаю на неё.` |
| Пересланное сообщение | Только его текст/вложения, без пометки «переслано от» |
| Аудио, видео, кружки, стикеры, геолокация, контакты, реакции | Не обрабатываются. Подпись, если есть, уходит как текст |

Вложения складываются в `inbox/` в каталоге данных демона и автоматически удаляются
через неделю.

**Сообщение посреди хода.** Пока Claude работает, новые сообщения встают в очередь темы и
обрабатываются после завершения хода по порядку. Пользователю один раз на ход приходит
`🕐 Дописываю текущий ход — это следующим.` Если очередь темы переполнена (128
сообщений), бот сообщает об этом и просит повторить, а не теряет сообщение молча.

## 5. Как приходит ответ

### 5.1 Ход в чате

1. Сразу после приёма сообщения бот показывает статус «печатает».
2. Если ход длится дольше 2 секунд или Claude вызвал инструмент, появляется **строка
   прогресса** — одно сообщение, которое редактируется по ходу работы. Под ней кнопка
   «🛑 Прервать».
3. Готовые куски ответа приходят обычными сообщениями (см. 5.3).
4. По завершении строка прогресса удаляется — **после** отправки ответа, чтобы мобильный
   клиент не оставался на устаревшем экране.
5. Опционально: подпись со статистикой хода и голосовое сообщение.

### 5.2 Строка прогресса

Формат: `<фраза> _<след инструментов>_ (<число вызовов> · <м:сс>)`, например
`копаю ⛏️ Grep → Read src/main.rs (4 · 1:12)`.

- **Фраза** выбирается случайно один раз на ход из трёх наборов, зависящих от прошедшего
  времени (до 20 с — «уже смотрю 👀», «поехали 🚀»; до 2 мин — «копаю ⛏️», «вникаю 🤔»;
  дольше — «завари чай, я ещё вожусь 🍵» и т.п.). Она не дёргается между перерисовками,
  но меняется при переходе в следующий временной диапазон.
- **След** — последние три имени инструментов через `→`. Для текущего вызова
  показывается одна деталь из его входа, одна строка, не длиннее 60 символов:
  путь файла для Read/Edit/Write/NotebookEdit, команда для Bash, шаблон для Grep/Glob,
  описание для Task, URL для WebFetch, запрос для WebSearch. Пути обрезаются спереди
  (`…/src/main.rs`), команды — сзади (`cargo test…`). Для остальных инструментов, включая
  все MCP-инструменты, показывается только имя: во входе может лежать секрет.
- Перерисовка не чаще раза в 4 секунды (при стриминге — в 3), потому что правки сообщений
  расходуют тот же лимит Telegram на чат, что и сами ответы.

**Предпросмотр ответа** (`stream_partial = true` в конфиге): под строкой прогресса
показывается хвост ответа, который Claude пишет прямо сейчас (последние 600 символов).
Это именно предпросмотр — готовый ответ всё равно приходит отдельным сообщением целиком.
Текст подагентов (Task) и размышления модели в предпросмотр не попадают.

### 5.3 Доставка текста

- Текст ответа отправляется по естественным границам: при каждом вызове инструмента (то,
  что модель написала до вызова, уходит сразу), при накоплении 3000 символов и в конце хода.
- Одно сообщение Telegram — не больше 4000 символов. Длинный текст режется по границам
  строк; блок кода при разрезе закрывается в одном сообщении и открывается заново с тем
  же языком в следующем, так что разметка никогда не ломается.
- Если ответ целиком больше 12 000 символов, он отправляется одним **файлом** `answer-….md`
  с исходным markdown и подписью `Ответ целиком — в файле.`
- Если один из кусков не удалось доставить: `⚠️ Часть ответа не доставлена.`

**Поддерживаемый markdown** (конвертируется в форматирование Telegram):

| Поддерживается | Не поддерживается (приходит как обычный текст) |
|---|---|
| Блоки кода ` ``` ` с подсветкой языка | Заголовки `#` |
| Инлайн-код `` `x` `` | Маркированные и нумерованные списки (маркеры остаются символами) |
| `**жирный**`, `*курсив*` | Таблицы, цитаты `>`, зачёркивание, подчёркивание, спойлеры |
| `[ссылка](url)` | Разделители, чекбоксы |

Одиночная `*` (например, `2 * 3`) остаётся как есть. Если Telegram отвергает разметку,
сообщение повторно отправляется как простой текст без тегов — ответ не теряется.

### 5.4 Сообщения в конце хода

| Ситуация | Сообщение |
|---|---|
| Ход завершён, но текста в ответе не было (только инструменты) | `✔️ Готово — в ответе не было ни слова текста.` |
| Claude Code вернул ошибку хода | `⚠️ Ход завершился с ошибкой.` |
| Инструменты были отклонены без вопроса пользователю (см. раздел 6) | `🔒 Отклонено без спроса: <инструменты>` + совет сменить режим прав |
| `show_turn_stats = true` в конфиге | Курсивная подпись `1 м 12 с · $0.08 · 3 шага` под ответом. Цена показывается только если Claude Code её сообщил (на подписке её нет) |

### 5.5 Обрыв хода

Строка прогресса заменяется на вердикт, кнопка убирается:

| Причина | Вердикт |
|---|---|
| `/cancel` или кнопка «🛑 Прервать» | `🛑 Прервано.` |
| Ход длился дольше `turn_timeout_secs` (по умолчанию 60 мин) | `⏱ Ход шёл дольше лимита и был прерван. Контекст сохранён.` |
| Процесс `claude` упал (после одной незаметной автоматической попытки повтора) | `💥 Процесс claude завершился (причина).` + последние строки stderr + `Контекст сохранён — /retry повторит ход.` |
| Демон остановлен во время хода | `⏹ Демон остановлен посреди хода. Контекст цел — /retry повторит.` |

Во всех случаях контекст сохраняется, `/retry` повторяет ход.

### 5.6 Гарантии доставки

Все сообщения бота (текст, файлы, голосовые) сначала записываются в очередь на диске и
снимаются с неё только после подтверждения Telegram. Недоставленное из-за падения демона
уезжает при следующем старте (доставка «хотя бы раз»: в редком случае сообщение может
прийти дважды). Ограничения Telegram (429) отрабатываются ожиданием и повтором, причём
отдельно на каждый чат-с-темой: чат, которому Telegram выдал паузу, не задерживает остальные.

## 6. Разрешения на инструменты

### 6.1 Режимы

`permission_mode` в конфиге — обязательное поле без значения по умолчанию: демон даёт
всем из `allowed_users` запускать Claude Code на этой машине с телефона. Режим можно
переопределить для одной темы командой `/perm`.

| Режим | Поведение |
|---|---|
| `prompt` | Каждый запрос разрешения, который Claude Code не решил сам по своим правилам, приходит в Telegram кнопками. Рекомендуемый режим |
| `acceptEdits` | Правки файлов проходят сами, всё остальное, что требует вопроса, молча отклоняется |
| `plan` | Режим планирования Claude Code, без изменений на диске |
| `manual` | Обычный режим вопросов Claude Code, но спросить некого — отклонение |
| `dontAsk` | Всё, что потребовало бы вопроса, отклоняется сразу |
| `auto` | Встроенный классификатор Claude Code пропускает безопасное; рискованное требует подтверждения, которого в этом режиме дать некому — отклонение |
| `bypassPermissions` | Проверок нет вообще. Полный shell с телефона |

Практический вывод: без `prompt` любой режим, кроме `bypassPermissions`, рано или поздно
упирается в молчаливый отказ. Чтобы отказ не выглядел как «бот сломался», всё отклонённое
без вопроса перечисляется отдельным сообщением `🔒 Отклонено без спроса: …` в конце хода.

### 6.2 Запрос разрешения в Telegram (режим `prompt`)

Когда Claude Code хочет вызвать инструмент, в тему приходит сообщение:

```
🔐 Bash просит разрешение
{ "command": "cargo test" }        ← вход инструмента, до 700 символов
```

с кнопками:

- **✅ Allow** / **❌ Deny** — разрешить или отклонить этот вызов;
- **🔓 Всегда: <правило>** — отдельной строкой ниже, только когда правило допустимо.
  Записывает постоянное разрешение **в эту тему**, и дальше такие запросы бридж
  разрешает сам, никого не спрашивая.

Границы «Всегда» жёсткие:

| Инструмент | Что запишет кнопка |
|---|---|
| `Read`, `Grep`, `Glob`, `NotebookRead`, `TodoWrite` | Имя инструмента целиком |
| `Bash` | Ровно эта команда, без шаблонов (`Bash(git status)`). Кнопки нет, если команда многострочная или длиннее 120 символов |
| `Edit`, `Write`, `NotebookEdit`, `WebFetch`, любые MCP-инструменты и всё остальное, что пишет | Кнопки нет. Ответ на «хочу, чтобы правки проходили сами» — осознанный `/perm acceptEdits` |

После нажатия сообщение редактируется: кнопки убираются, снизу дописывается
`✅ разрешено`, `❌ отказано` или `🔓 разрешено, и больше не спрошу: <правило>`. Нажавший
видит всплывающий тост. Кнопка от уже обработанного или устаревшего запроса (например,
после перезапуска демона) отвечает тостом «Запрос уже неактуален» и ничего не делает.

Без ответа в течение `permission_timeout_secs` (по умолчанию 10 минут) — отказ. Если
демон недоступен, Claude Code также получает отказ с текстом причины. Зависания
«навсегда» не бывает.

`/perm` показывает накопленные правила темы, `/perm forget` забывает их все.

### 6.3 Правила поверх режима

Тонкая настройка не вместо режима, а вместе с ним: рутина проходит по правилам без единой
кнопки, всё остальное попадает в `prompt`. Эти настройки глобальные (в конфиге) и
передаются Claude Code напрямую:

```toml
allowed_tools    = ["Read", "Grep", "Glob", "Bash(git status:*)", "Bash(git diff:*)"]
disallowed_tools = ["Bash(rm:*)", "WebFetch"]
tools            = ["Read", "Grep", "Glob", "Bash"]     # какие инструменты вообще существуют
settings         = "~/.config/claude-tg/settings.json"  # путь или JSON строкой
add_dirs         = ["~/src/shared"]                      # доступ за пределы директории темы
```

Часть вызовов Claude Code разрешает сам по своим встроенным правилам, и до кнопок они не
доходят: `prompt` означает «спрашивать там, где положено спрашивать», а не «кнопка на каждый
чих».

## 7. Функции Claude Code через мост

Claude Code запускается в неинтерактивном режиме с потоковым JSON-протоколом на входе и
выходе. Один процесс на тему живёт долго и принимает много ходов подряд; при простое он
гасится, а контекст остаётся в транскрипте Claude Code и поднимается через `--resume`.

Базовая командная строка:

```
claude -p --verbose --input-format stream-json --output-format stream-json
       --permission-mode <режим>
       [--allowed-tools …] [--disallowed-tools …] [--tools …] [--settings …] [--add-dir …]
       --session-id <uuid>            # первый запуск темы
       --resume <uuid>                # все последующие запуски
       [--include-partial-messages]   # при stream_partial
       [--model <имя>]
       [--append-system-prompt-file <SOUL.md>]
       [--mcp-config <конфиг MCP-сервера разрешений> --permission-prompt-tool mcp__claude_tg__approve]   # режим prompt
```

Рабочая директория процесса — директория темы. Режим `prompt` со стороны Claude Code —
это `--permission-mode manual` плюс инструмент запроса разрешений, который предоставляет
сам мост как MCP-сервер.

### 7.1 Матрица поддержки

| Возможность Claude Code | Поддержка | Как это работает в Telegram |
|---|---|---|
| Многоходовый разговор с сохранением контекста | ✅ | Каждое сообщение в теме — ход в одной сессии. Контекст хранится в транскрипте Claude Code |
| Возобновление сессии (`--resume`) | ✅ | Автоматически после простоя, `/stop`, перезапуска демона и смены настроек. `/sessions` + `/resume` подключают любую сессию, в том числе начатую в терминале, с её директорией |
| Новый контекст (`/clear`) | ✅ | `/new` или `/clear` — новый session id, старый транскрипт остаётся |
| `/compact` | ✅ | Уходит в Claude Code как обычный ход. Ход завершается корректно, даже если текста в ответ не пришло |
| Другие slash-команды CLI (`/agents`, `/doctor`, …) | ✅ | Любая неизвестная демону `/команда` передаётся как есть |
| Выбор модели (`--model`) | ✅ | Глобально в конфиге, для темы — `/model` |
| Режимы прав (`--permission-mode`) | ✅ | Все режимы; для темы — `/perm`. Режим `prompt` — кнопки в Telegram |
| Запросы разрешений (`--permission-prompt-tool`) | ✅ | Сообщение с кнопками ✅/❌/🔓, таймаут → отказ, постоянные правила на тему |
| `--allowed-tools`, `--disallowed-tools`, `--tools` | ✅ | Ключи `allowed_tools`, `disallowed_tools`, `tools` конфига |
| `--settings`, `--add-dir` | ✅ | Ключи `settings`, `add_dirs` |
| Дополнение системного промпта | ✅ | Файл персоны через `--append-system-prompt-file`, см. раздел 8 |
| Plan mode | ✅ | `/perm plan` |
| Отображение вызовов инструментов | ◐ | Только имена и одна деталь на строке прогресса. Полного лога вызовов нет |
| Вывод инструментов (результаты Bash, содержимое файлов, диффы) | ❌ | Не показывается. Видно только то, что модель сама пишет в ответе |
| Размышления (extended thinking) | ❌ | Не показываются ни в ответе, ни в предпросмотре |
| Подагенты (Task) | ◐ | На строке прогресса как `Task <описание>`. Текст подагентов в ответ не попадает |
| TodoWrite, планы, список задач | ❌ | Не отображаются отдельно |
| Стриминг ответа | ◐ | Предпросмотр хвоста на строке прогресса при `stream_partial`; готовый ответ — отдельным сообщением |
| Время, число шагов, стоимость хода | ✅ | В `/status` («Последний ход») и подписью под ответом при `show_turn_stats`. Стоимость — если CLI её сообщает |
| Прерывание хода | ✅ | `/cancel` или кнопка «🛑 Прервать»: процесс останавливается, контекст цел |
| Очередь сообщений во время хода | ✅ | Сообщения ждут завершения хода, порядок сохраняется, одно предупреждение на ход |
| Вложения в промпт (изображения, файлы) | ◐ | Файл скачивается на машину, Claude получает путь и читает его сам инструментом Read. Изображение не вкладывается в сообщение как картинка |
| Голосовой ввод | ✅ | Через внешнюю команду транскрипции (раздел 9) |
| MCP-серверы пользователя | ◐ | Мост подключает только собственный MCP-сервер разрешений. Свои серверы — через `settings` или конфигурацию Claude Code |
| Собственные инструменты моста для модели («отправить файл в Telegram» и т.п.) | ❌ | Нет намеренно: доставку выполняет демон, а не модель |
| Hooks | ◐ | Мост их не настраивает; работают, если заданы в `settings` или конфигурации Claude Code |
| Одновременные сессии | ✅ | Без ограничений, по одной на тему |

### 7.2 Что мост делает с событиями Claude Code

- Текстовые блоки ответа → сообщения в чат.
- Вызовы инструментов → строка прогресса.
- Частичные фрагменты текста (при `stream_partial`) → предпросмотр. Фрагменты подагентов
  и размышлений отбрасываются.
- Событие завершения хода → конец хода: удаление строки прогресса, статистика, список
  отклонённых без вопроса инструментов, признак ошибки. Ход завершается **только** по этому
  событию, поэтому ход без текста (например, `/compact`) не подвешивает тему.
- Если Claude Code сообщает session id, отличный от ожидаемого (это случается после
  `/compact`), тема принимает новый id, чтобы последующее возобновление не откатило
  разговор к старому состоянию.
- Результаты инструментов, размышления, служебные и статусные события игнорируются.

## 8. Персона (SOUL)

Файл персоны дописывается к системному промпту Claude Code (`--append-system-prompt-file`),
и бот отвечает своим голосом — например, от женского лица и от своего имени. Имя и аватар
бота в шапке чата задаются у @BotFather, а не здесь.

- `claude-tg init` кладёт стартовый файл в `~/.config/claude-tg/SOUL.md` (персона «Ада»:
  женский род, спокойный прямой тон, короткие ответы под Telegram, длинный вывод — в файл
  или блок кода, при неоднозначности спрашивать).
- Если в конфиге `soul` не задан, но этот файл существует, он используется автоматически.
- В конфиге можно указать любой путь, например файл в своём репозитории, чтобы правки
  версионировались.
- Для темы: `/soul <путь>`, `/soul off`, `/soul default`; текущее значение — в `/status`.
- Файл читается при каждом запуске процесса, поэтому правка вступает в силу после `/stop`
  или простоя. Контекст при этом остаётся. Пропавший файл не ломает тему: процесс
  запускается без персоны.

`examples/SOUL.nova.md` — живой пример персоны «Нова»: обращение к собеседнику по имени и
на «ты», тёплый разговорный тон с уместными эмодзи и лёгкой иронией, правила формата под
чтение с телефона (проза вместо списков, длинный вывод в код или файл), сколько инициативы
брать на себя (доделывать очевидное, спрашивать до начала при неоднозначности, один раз
возразить и затем выполнить), чего не делать (не приукрашивать, не льстить, не изображать
уверенность) и напоминание, что она видит только сообщения этой темы и у каждой темы своя
директория.

## 9. Голос

Оба конца звука — внешние shell-команды из конфига, поэтому движок меняется одной строкой.

### 9.1 Голосовые ответы (TTS)

`/voice on` включает для темы озвучку ответов. Текст приходит всегда; голосовое — дополнение.

- На ход отправляется **одно** голосовое, после всего текста ответа.
- Вслух читается только проза: блоки кода и инлайн-код выбрасываются, символы разметки
  (`*`, `#`, `_`, `>`) удаляются, пустые строки схлопываются. Текст обрезается до 900
  символов по границе предложения. Если после чистки осталось меньше трёх символов
  (ответ — сплошной код), голосовое не отправляется.
- Команда из ключа `tts` получает `{text_file}` (текст), `{wav}` (временный путь) и
  обязана записать OGG/Opus в `{out}` — только такой файл Telegram показывает как настоящее
  голосовое. Лимит времени — 2 минуты; при ошибке голосовое просто не приходит.

Вариант без зависимостей на macOS:

```toml
tts = "say -v Milena -f {text_file} -o {wav} --data-format=LEI16@22050 && opusenc --quiet {wav} {out}"
```

Живой голос — скрипт `voices/tts.sh {text_file} {wav} {out}` с двумя локальными движками,
выбираемыми переменными окружения:

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `NOVA_TTS_ENGINE` | `qwen` | `qwen` (Qwen3-TTS 1.7B на MLX, звучит как человек, ~0.3 от длительности речи на M4 Pro) или `silero` (Silero v5_ru на CPU, мгновенно, звучит как диктор, ударения верные) |
| `NOVA_TTS_VOICE` | `serena` / `baya` | Диктор выбранного движка (у Silero: aidar, baya, kseniya, eugene, xenia) |
| `NOVA_TTS_INSTRUCT` | тёплый разговорный тон | Подсказка по интонации, только qwen |
| `NOVA_TTS_HOME` | `~/.cache/nova-tts` | venv и веса |
| `NOVA_TTS_REPO` | Qwen3-TTS 1.7B 8bit | Другой чекпойнт |

Установка: `voices/setup.sh` (оба движка) или `voices/setup.sh silero` (только CPU). Нужны
python3, `opusenc` из `opus-tools`. Веса Qwen (~3 ГБ) скачиваются при первом синтезе.

### 9.2 Голосовой ввод (STT)

Ключ `transcribe` — команда, получающая `{file}` (скачанное голосовое, OGG/Opus) и
`{wav}` (временный путь); распознанный текст читается со стандартного вывода. Лимит —
3 минуты. Рекомендуемый вариант:

```toml
transcribe = "opusdec --quiet --rate 16000 --force-wav {file} {wav} && \
              whisper-cli -m ~/.cache/whisper/ggml-small.bin -f {wav} -l ru -nt -np -t 8 2>/dev/null"
```

(`brew install whisper-cpp opus-tools` плюс модель `ggml-small`). Распознанный текст
эхом возвращается в чат курсивом с 🎤, чтобы кривое распознавание было видно сразу. Если
команда не задана или упала, Claude получает путь к аудиофайлу.

## 10. Жизненный цикл сессии и процесса

**Создание темы.** Первое обычное сообщение или команда (кроме справочных) в чате/теме
создаёт запись темы: новый session id, директория из `defaults.cwd`, название чата. Процесс
`claude` запускается при первом ходе.

**Тёплый процесс.** Один процесс на тему обслуживает много ходов подряд. Через
`idle_timeout_secs` простоя (по умолчанию 30 минут) он гасится без сообщения в чат;
следующий ход поднимает его с тем же контекстом. Гашение всегда бережное: процессу дают
завершиться самому, чтобы он дописал транскрипт.

**Что перезапускает процесс, сохраняя контекст:** `/stop`, `/model`, `/perm`, `/soul`,
простой, падение, прерывание, остановка демона.

**Что начинает контекст заново:** `/new`, `/clear`, `/cd`, `/go`, `/project` (в новой теме),
а `/resume` подменяет контекст на выбранную сессию.

**Лимит хода** — `turn_timeout_secs` (по умолчанию 60 минут), после него ход прерывается с
сообщением.

**Падение процесса.** Ход автоматически повторяется один раз; если процесс упал снова,
пользователь видит `💥 …` с хвостом stderr. Если Claude Code сообщает, что session id уже
занят, тема незаметно переключается на возобновление.

**Остановка демона** (`claude-tg stop`, Ctrl+C, SIGTERM): идущие ходы прерываются с
сообщением в свои темы, процессам дают несколько секунд завершиться, очередь исходящих
досылается, в `notify_chat` уходит `⏹ Останавливаюсь.` с числом прерванных тем.
`claude-tg stop` возвращается только когда демон действительно вышел.

**После перезапуска демона:** темы, session id, директории, настройки тем, постоянные
разрешения и последний ход для `/retry` сохранены; недоставленные сообщения уезжают;
уже обработанные обновления Telegram не повторяются (повтор сообщения означал бы повторный
запуск shell-команды). Теряется только «Последний ход» в `/status` и кнопки старых
запросов разрешений (они отвечают «Запрос уже неактуален»).

## 11. Установка и конфигурация

```sh
cargo build --release            # ./target/release/claude-tg
./target/release/claude-tg init  # пишет ~/.config/claude-tg/config.toml и SOUL.md
claude-tg run                    # запуск демона (логи: CLAUDE_TG_LOG=debug)
claude-tg stop                   # остановка
```

Нужны: **отдельный бот** от @BotFather (Telegram допускает один опрос на токен, поэтому
с официальным плагином один токен делить нельзя); для многотемности — **супергруппа с
включёнными Topics** и право бота «Управление темами» (для `/project`); установленный
`claude`. Демон не ставится сервисом и живёт, пока живёт терминал.

Конфиг `~/.config/claude-tg/config.toml` (другой путь — `claude-tg run --config`):

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `bot_token` | — | Токен бота; переменная `CLAUDE_TG_BOT_TOKEN` имеет приоритет |
| `allowed_users` | обязателен | Кто может управлять ботом |
| `allowed_chats` | `[]` = везде | Где бот говорит |
| `notify_chat` | — | `"chat_id"` или `"chat_id:thread_id"` для уведомлений о старте/остановке |
| `[projects]` | `{}` | Алиасы директорий для `/go` и `/project` |
| `defaults.cwd` | обязателен | Директория новых тем |
| `defaults.permission_mode` | обязателен | Режим прав, см. раздел 6 |
| `defaults.model` | модель CLI | Модель по умолчанию |
| `defaults.claude_bin` | `claude` | Путь к CLI |
| `defaults.soul` | `~/.config/claude-tg/SOUL.md`, если есть | Файл персоны |
| `defaults.transcribe` | — | Команда распознавания речи |
| `defaults.tts` | — | Команда синтеза речи |
| `defaults.idle_timeout_secs` | 1800 | Простой до гашения процесса |
| `defaults.turn_timeout_secs` | 3600 | Лимит одного хода |
| `defaults.permission_timeout_secs` | 600 | Ожидание ответа на запрос разрешения |
| `defaults.show_turn_stats` | false | Подпись со временем/ценой/шагами под ответом |
| `defaults.stream_partial` | false | Предпросмотр ответа на строке прогресса |
| `defaults.allowed_tools`, `disallowed_tools`, `tools` | `[]` | Правила инструментов, см. 6.3 |
| `defaults.settings` | — | Файл или JSON настроек Claude Code |
| `defaults.add_dirs` | `[]` | Дополнительные директории |
| `defaults.neutralize_official_plugin` | true | Не даёт официальному Telegram-плагину, если он установлен, убить свой опрос в другой сессии |

Переменные окружения: `CLAUDE_TG_BOT_TOKEN` (токен), `CLAUDE_TG_LOG` (уровень логов),
`CLAUDE_CONFIG_DIR` (где искать транскрипты Claude Code для `/sessions`).

Данные демона лежат в `~/.local/share/claude-tg`: состояние тем, очередь исходящих,
скачанные вложения (`inbox/`, чистятся через неделю), временные файлы. Всё создаётся с
правами только для владельца.

## 12. Ограничения и особенности

- Стриминг — предпросмотр на строке прогресса, а не само сообщение; готовый ответ приходит
  отдельно и целиком.
- Не показываются размышления модели, вывод инструментов, диффы и списки задач — только
  то, что модель пишет в ответе, и имена инструментов на строке прогресса.
- Markdown поддерживается частично: заголовки, списки и таблицы приходят обычным текстом.
- Изображения передаются Claude как путь к файлу, а не как картинка в сообщении.
- `allowed_chats` по умолчанию пуст: бот отвечает в любом чате, откуда пишет разрешённый
  пользователь.
- Доставка «хотя бы раз»: при падении демона между отправкой и подтверждением сообщение
  может прийти дважды.
- Застрявшее исходящее сообщение держит свою тему до ~10 минут; остальных тем это не касается.
- Одну сессию нельзя держать открытой одновременно в терминале и в Telegram.
- Распознавание речи идёт на CPU и занимает примерно вдвое больше времени, чем длится запись.
- Демон не устанавливается как системный сервис.
