# PHASE_3_STREAMING — живой индикатор, рендер, кнопки

Status: all phases done — draft/прогресс, сплиттер, кнопки, карточка; tests green (85 passed)

## Why

Фаза 2 показывает ответ только по завершении текстового блока, а управляет всем через
слеш-команды. Эта фаза даёт «живое» ощущение работы модели (draft с размышлениями и следом
инструментов в личке, редактируемое сообщение-прогресс в группах), корректный рендер длинных
ответов и переводит управление на нативные кнопки (PROJECT_SPEC 4.3.0).

## Verified facts

- Bot API 10.3 / aiogram 3.31: `sendRichMessageDraft(chat_id, draft_id, rich_message,
  message_thread_id, can_stop, keep_on_stop)` только в личных чатах, ~30 с жизни,
  `<tg-thinking>` только в draft; `Update.stopped_message_generation{chat, message_thread_id,
  draft_id}` (PROJECT_SPEC 2.2).
- Stream-события: `text_delta`, `thinking_delta`, `content_block_start:tool_use`; `assistant`
  по одному блоку (PHASE_0_SPIKE 6).
- `editMessageText` на тот же текст → `TelegramBadRequest: message is not modified` — assumed
  по опыту Bot API, обрабатывается как no-op.

## Decisions

| Вопрос | Решение |
|---|---|
| Режимы индикатора | `draft` — личный чат и `USE_DRAFTS`; `message` — группы/форумы или отказ Telegram от draft; в обоих один шлюз trailing-edge (`DRAFT_MIN_INTERVAL` / `EDIT_MIN_INTERVAL`), 429 закрывает шлюз на `retry_after`. |
| Что в draft | `<tg-thinking>` с строкой прогресса и последней строкой размышлений (≤300 символов, `THINKING_PREVIEW`), ниже — накопленный текст текущего сегмента (не раньше 50 символов, без последнего слова, замораживается на 30 000 с ` ⏳…`). `can_stop=True`; keepalive каждые `DRAFT_KEEPALIVE` с при долгих инструментах. |
| Что в сообщении-прогрессе | Plain-текст: строка прогресса и (при `STREAM_PREVIEW`) хвост текста ≤ 600 символов; кнопка `🛑 Прервать`. Отправляется напрямую (не через outbox, эфемерно) через `PROGRESS_DELAY` после начала хода или при первом событии; удаляется через outbox **после** финальных сообщений. Если правка упала (сообщение удалили) — следующее обновление создаёт новое. |
| Строка прогресса | `<фраза> <след> (<N> · <м:сс>)`; фраза случайна в пределах диапазона времени и меняется при переходе диапазона; след — последние 3 инструмента через ` → `, у текущего одна деталь ≤ 60 символов (Read/Edit/Write/NotebookEdit — путь, срез спереди; Bash — команда, срез сзади; Grep/Glob — шаблон; Task/Agent — описание; WebFetch — URL; WebSearch — запрос; MCP и прочие — только имя); подагент — `Task ▸ <имя>`. |
| Сегменты текста | `assistant[text]` копится в `pending`; отправляется, когда `len(pending) ≥ MIN_SEGMENT_CHARS` (120), при `result`, или когда превысил 30 000. Так «Посмотрю файл.» перед tool call не становится отдельным сообщением. |
| Длинный ответ | Сегмент длиннее `ANSWER_FILE_THRESHOLD` (50 000) → первые 2 000 символов rich-сообщением + файл `answer-<turn>.md` в `INBOX_DIR/out/` документом с подписью. |
| Сплиттер | `split_markdown(text, 30 000)`: разрез назад по `\n\n`, `\n`, `. `, пробелу; открытый ``` закрывается в конце чанка и переоткрывается с тем же языком; строки таблицы не режутся посередине блока. |
| Кнопки | `callback_data = <action>:<topic_id>[:<arg>]`. Действия: `cancel`, `retry`, `new`, `stop`, `perm` (arg = режим), `continue`, `refresh`, `hide`. Команда и кнопка вызывают одну функцию из `app/core/actions.py`. Устаревшая кнопка → тост «Уже неактуально». |
| Карточка темы | `/status` присылает карточку (текст 4.2 + кнопки). В этой фазе: `🛑 Прервать` (если идёт ход) · `🆕 Новый контекст` `⏸ Стоп процесса` · `🔄 Обновить` `✖ Скрыть`. Переключатели прав/модели/усилия — фаза 7; `📁 Проект…`, `🧹 Сжать` — фазы 6/7. |
| Меню «/» | `status`, `new`, `help` (+ `project` в фазе 6). |
| Вердикты | `🛑`/`💥`/`⏱` → `🔁 Повторить`; `🔒` → `🔓 Разрешать правки`, `🔁 Повторить`; `⏹ лимит` → `▶️ Продолжить`; хинт `🕐` → `🛑 Прервать текущий`. |

## Phase results

- Всё из Deliverables; `bash scripts/test.sh` — 85 passed (~21 с).
- Правило «без последнего слова, не раньше 50 символов» применяется и к draft'у (пока идёт
  текстовый блок), не только к сообщению-прогрессу.
- Сплиттер: проверка «хвост начинается с таблицы» должна снимать ведущий `\n`; таблица длиннее
  лимита всё же режется по строкам (иначе никак).
- Карточка считает ход идущим и при непустой очереди (гонка между `submit` и стартом воркера).
- Рендер `<tg-thinking>` в клиентах — на smoke.

## Manual smoke checklist

1. Личка: длинный вопрос → draft с `<tg-thinking>` и растущим текстом; нативный Stop прерывает.
2. Тема в личке: то же самое внутри темы.
3. Карточка `/status`: кнопки работают, карточка перерисовывается, `✖` убирает.
4. Ответ с таблицей и кодом рендерится; очень длинный ответ приходит файлом.
5. Группа без drafts (если будет): сообщение-прогресс редактируется и исчезает после ответа.
